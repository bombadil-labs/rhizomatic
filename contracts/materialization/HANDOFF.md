## Nonnegotiable state/fault semantics

Source final check defines the basis; metadata CAS selects it atomically. Changes after check
before CAS can leave the new selection stale and MUST be detected on next read. There is no
cross-store lease or latest-at-commit promise. Read/advance take an explicit snapshot carrier
matching stored capture commitment and perform fresh authorization/currentness checks.

Control persists active descriptor support and payload-free retired terminal metadata, immutable pins/definition-at, accepted
source revision/authority/capture metadata, time and latest signed transition; source/result
payloads are disposable; active program support is a declared host erasure surface, including
historical image/temp/WAL copies. Retire every consumer and purge all copies before settlement. The native current check receives
explicit exact closure/descriptor requiredSupport IDs and delegates to existing host refusal facts,
so programs sharing a binding need no hidden request context or duplicated erasure interpreter.
Retired reopen never reacquires original descriptor/definition payload. Fresh source carrier signing never needs the old native capture signer:
reconstruct exact committed snapshot bytes from metadata+current verified rows, then check
present authority independently. If bytes/basis cannot be reacquired, unavailable/stale selection
is visible and no old value is current. Retention is inert; names/aliases cannot activate state.

Before CAS failure leaves prior state. After durable CAS, rebuild/signing/delivery failure cannot
be a known refusal. Uncertain CAS discards native state and requires reopen; absent/present
branches restore prior/new complete state respectively. Multiwriter conflict returns to host for
explicit re-read/new attempt. Retirement remains terminal after restart; native cache loss changes
no declared state. One configuration has a 64-entry lifetime bound; capacity rotation prepares a
separate scope and explicitly durably selects its boot configuration, not a portable cross-scope
transaction. Loam's selected batch door makes one attempt without control CAS or retry/fallback.
See SPEC's effect and crash tables for exact codes/order/results.
