# M2 batch implementation and review handoff

[SPEC-16](../../spec/16-materialization.md) is the sole normative behavior owner. This slice
implements batch gather, pure evidence resolve, supplied-input preflight and contextual result
readback in TypeScript and Rust. It is awaiting independent Fable review and supervisor integration;
these local gates are not release approval. No M3 maintained lifecycle, M4 cumulative acceptance or
M5 Loam route is implemented here. The six deferred lifecycle variants remain explicitly allocated
in [M2-VARIANTS.json](M2-VARIANTS.json) and M3's cumulative manifest.

## Ports and capabilities

| Existing owner | TS / Rust ports |
| --- | --- |
| command-data | materializationDescriptionClaims / materialization_description_claims; readMaterializationDescription / read_materialization_description; limits codec |
| federation | original appearance and source snapshot codecs; capture-basis validation; MaterializationSourceCapability / MaterializationSourceCapability |
| schema-load | original signed definition extraction and exact reachable closure; existing native grammar |
| resolve | evalMaterializationTerm / eval_materialization_term_at, bounded native evaluator; thin evidence bridge to algebra |
| command | MaterializationEndpoint, preflightMaterializationInput / preflight_materialization_input, readMaterializationResult / read_materialization_result |

Root barrels expose selected typed ports; module exports, methods, aliases and dependency edges are
classified in the existing live command inventories. Algebra retains the M1 envelope owner and
resolve-kernel retains policy resolution. No command-owned second evaluator or source registry is
introduced. The native default evaluator and profile1 remain unbounded by these new profile limits.

Boot receives verified signed configuration/declarations/bindings, an explicit receiver signer,
native source grants and a diagnostic sink. Retaining matching descriptions in a journal does not
install capabilities. Invocation receives entry ID, copied delivered appearances and finite trusted
receivedAt. The request separately binds operand at, definition-at and serving-at. Source checkCurrent
gets the identical explicit sorted support set at both checks; actual fixture hosts derive decisions
from current row inventories and refusal facts. Pure resolve interprets caller-owned evidence without
present source authorization or currentness claims. A contextual reader verifies structure,
commitments and receiver testimony; it cannot prove the receiver executed the stated computation.

Preflight projects the supplied-input checks in SPEC-16, including stage-8 resolve-envelope bounds.
It omits native authorization/currentness and never evaluates an output. input-valid is neither a
permission nor a dispatch/output-capacity guarantee. Known input overflow may exclude the portable
route before dispatch; an invoked output overflow is a visible refusal with no fallback. Applications
retaining carriers, evidence or outcomes retain full payload copies and own their erasure surfaces.

## Executed allocation and oracles

[M2-CASES.json](M2-CASES.json) maps all **27 ::batch** obligations to specific assertions.
The corpus contains 25 command successes, 110 command refusals and 15 contextual-reader rejections;
9 description and 10 source codec vectors are additional independent contracts. Expected full signed
outcomes and CBOR bodies are constructed from established C/hash/sign primitives and manually
specified HViews/Views. The generators do not import the M2 endpoint/evaluator/readback or source
codec. Description bytes have a separate Python grammar oracle. Witness agreement is supplementary.

The acceptance gate checks exact corpus commitments, vector identities and executed assertion
counts, with missing/count/identity/commitment sensitivity negatives. Counts and metadata do not
prove arbitrary assertion meaning. Native TS schedules cover copied asynchronous inputs and
interleaved receive times; safe owned/borrowed Rust invocation slices cannot express concurrent
native-object mutation, which is stated as a type limitation rather than a fabricated async port.
Both witnesses execute real inert profile1 journal retention and explicit-time/framing/privacy probes.

Produced-tree vectors distinguish logical intermediates from final-only limits, per-node buckets
from aggregate counts, active expansion depth, global child budgets from parent attachment budgets,
replacement, prune and non-cumulative wrappers. TS spies and Rust invocation-local cfg(test) traces
check deterministic early stopping; Rust traces additionally assert one pending child per active
frame. No wall-clock admission threshold, cumulative work quota or single global temporary is claimed.

The serialized five-stage command graph runs eight required families in both fixed directions
(**16 crossings**) and three seeded assignments each (**24 towers**), then exact replay. Three
hostile families additionally execute **15 refusal branches**, terminating after gather and fresh
contextual refusal readback; wrap/resolve are not dispatched. Full independent expected outcomes
are kept outside adapter inputs. Build fingerprints, original stage artifacts and seven sensitivity
negatives are retained. Elixir/Haskell remain Level 0 and advertise no materialization stages.

## Reproduce and evidence

From the repository root, with Node/npm and stable cargo/rustc on PATH, serialize heavy suites:

```
node contracts/materialization/validate.mjs --self-test
node tools/check-command-contracts.mjs --self-test
node tools/check-package-graph.mjs
node tools/check-rust-command-boundaries.mjs
node --test tools/check-materialization-accounting.test.mjs tools/check-rust-command-boundaries.test.mjs
npm run check --prefix implementations/ts
cargo fmt --check --manifest-path implementations/rust/Cargo.toml
cargo clippy --locked --all-targets --manifest-path implementations/rust/Cargo.toml -- -D warnings
cargo test --locked --manifest-path implementations/rust/Cargo.toml
node tools/check-materialization-acceptance.mjs
node tools/check-materialization-towers.mjs --replay artifacts/materialization-m2
node tools/measure-materialization.mjs
node tools/check-evidence-acceptance.mjs
node tools/check-evidence-towers.mjs --replay artifacts/materialization-m1
npm run gen-materialization-vectors --prefix implementations/ts
npm run docs:build --prefix implementations/ts
```

M2_ARTIFACT_DIR and M2_SEED select recorded output/seed; CARGO_TARGET_DIR selects external Cargo
artifacts and the harness uses Cargo's reported executable, not an assumed target path. Measurement
instrumentation lives only in disposable copies. CI retains all four native gates, profile1, M0/M1,
original vector/docs freshness and adds M2 acceptance/replay/measurements. The profile1 final
acceptance gate requires actual exact-commit four-witness hosted evidence; local missing GHC/older
Elixir are not substituted with fabricated conformance. Native runtime tests and its transport/
boundary/tower regressions can still execute locally.

Ignored artifacts/materialization-m2 contains REPORT.json, COVERAGE.json, VECTOR-ASSERTIONS.json,
TS-TESTS.json, Rust logs, CAPABILITIES/EVIDENCE and concrete plans/stages. REPORT.json pins source
commit/tree/clean state when run after freeze. [M2-RESULTS.md](M2-RESULTS.md) records local gates and
performance limits. A dirty working-tree report is preliminary and does not pin the frozen build.

## Release-A practical limits and call boundaries

The source4096 preliminary sweep uses 4,096 full source appearances and a 3,293,968-byte snapshot.
TS gather is **26.05 s**, resolve **8.22 s**; Rust release gather **1.17 s**, resolve **0.37 s**.
Whole TS child-process peak is **1,120,440 KiB**, Rust **173,640 KiB**. These observations establish
neither a serving SLA nor a per-phase memory claim. The separate 4097 fixture deterministically
refuses resource-limit without truncating/filtering its source.

| source4096 phase | Real strict signature verifier calls | Boundaries represented |
| --- | ---: | --- |
| Fixture-native capture acquisition | 8,195 = 2N+3 | Full snapshot decode plus separate capture-basis validation; fixture host, no Loam I/O or generic fresh capturer claim |
| Endpoint boot | 4 | Selected signed boot descriptions |
| Gather | 12,299 = 3N+11 | Source decode N, capture-basis validation re-decode N, output-envelope encode N; delivered/program/outcome checks add 11 |
| Gather contextual readback | 12,312 = 3N+24 | Two snapshot validation passes plus one envelope decode and remaining context/definition/outcome checks |
| Resolve | 4,111 = N+15 | One supplied-envelope decode; original Basis/program/appearance checks add 15 |
| Resolve contextual readback | 12,313 = 3N+25 | Two snapshot validation passes plus one envelope decode and remaining context/definition/outcome checks |

Each M1 encode/decode invocation still verifies once per distinct full appearance, including the
final decoder re-encode. Separate invocations do not share verification caches. The duplicate
snapshot decode within source/Basis validation is a concrete bounded avoidable-work candidate for
Fable's release-A assessment; this slice keeps validation and authorization behavior unchanged.
No Delta.id-only, global or cross-call cache is added, and fresh current-support checks remain live.

RSS is measured by /usr/bin/time for the entire fresh child: parsed full fixtures (including retained
independent goldens/carriers), live native phase inputs/results, runtime/GC and scalar verifier
instrumentation coexist. Parent bundler/compiler memory is excluded. There is no phase-level RSS
attribution or retained-golden subtraction experiment. The scalar increments count actual strict
verification calls, not an alternative verifier; independent complete byte goldens still apply.
Fixed Bed/Plant and source-size 0/128/1024/4096/4097 measurements are observations, not CI timing
thresholds. M3 install/replacement/restore and actual Loam measurements remain deferred.
