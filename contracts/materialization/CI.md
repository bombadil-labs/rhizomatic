# Gates and evidence

## M0 structural gate

Run `node contracts/materialization/validate.mjs --self-test` and `git diff --check`.
The local validator checks exact MR inventory and mapping, unique stable case IDs, independent
milestone allocation, dependency DAG, prospective API classifications, stage/contract refs,
three-tower/fixed-route/replay requirements, preserved witness levels and finite limits. Negative
mutations prove missing cases, changed ownership, unknown requirements, invalid limit/dependency,
false capability claims and removed replay requirements fail for the intended reason. Repair
checks cover finding dispositions/case refs, preserved ten Loam schedule IDs, compact public
Basis and shared multi-root shape, explicit native observation/support-set APIs and replay fields. This is
contract consistency evidence, not runtime conformance. No heavy witness suites are required for
this documents-only slice. Existing command contract/graph checks should still pass.

## Implemented milestone gates

1. Materialize the milestone's exact ACCEPTANCE cases as shared fixtures and named executable
   integrations. Compare canonical envelope/body/control/View bytes against independently
   reviewed goldens, then witness parity. Do not use a generator as its own oracle.
2. TS `npm run check`; Rust fmt/clippy/tests, serialized locally; all existing profile-1 tests
   and lower witness gates remain required. TS source changes include committed docs:build output.
3. Extend current command/public export inventory and checked source graph for prospective API.json
   entries, classifying actual new APIs rather than pretending current cards certify future code.
   Type-only, dynamic and aggregate upward imports remain forbidden. Record real symbol mapping
   for Rust shared modules; do not claim a crate split.
4. Execute both fixed mixed routes and the milestone's three seeded supported towers. Save exact
   replay artifacts even on failure; replay them without randomness. M3 uses fresh processes for
   cross-witness restore and real fault termination before/after CAS. Do not swap native reactors.
5. Emit `rhizomatic-conformance-report/1`, exact clean source commit, measured build/toolchain,
   profile/port versions, discovered non-skipped case IDs, actual artifacts and statuses. No plan
   JSON or old profile-1 evidence may certify a new capability.
6. Independent Fable review assesses the frozen commit; supervisor collects/fixes findings and owns
   acceptance/integration/merge/release. Automated evidence cannot impersonate that review.

Milestone requirements are cumulative through M4. M5 adds Loam's ten real-door schedules and all
current boundary/cycle tests plus negative bystanders. A scoped production replacement must call
the reviewed published package; a codec-only test shim cannot satisfy M5.

New profile capability declarations are prospective until the corresponding exact-version ports
have new executed evidence. Release A advertises M1/M2 only; M3 operations refuse unsupported.
Release B needs all M0–M4 and review. Actual prerelease versions are supervisor decisions at release
time; no tag/release is authorized by this packet's M0 builder assignment.

## Harness failure proofs

Require: unsupported-stage manifest; missing/skipped case; stale build; modified replay artifact;
noncanonical incoming envelope; wrong reading metadata with equal semantic pin; deliberately
wrong common final View shared by all towers; wrong control selected after scheduled crash;
and state leakage between towers. Each must fail at its named gate, not merely crash a runner.
Boundary corruption and common-wrong-answer are different failures and both are required.

## Measurement without semantic compromise

Record canonical source/envelope/control/result byte lengths, signature count, wall time and
peak memory for the fixed nested Bed→Plant fixture (32 plants, four buckets each, 128 signed
facts, bytes leaf, two-level expansion), in both witnesses before optimization. Record cold
capture, gather, readback, resolve, install, replacement and fresh restore/read separately. Add a
source-size sweep at 0, 128, 1024, 4096 and 4097 TOTAL selected appearances (including selected law
if it belongs to the source). Record snapshot/capture/carrier/delivery/result bytes and every
signature verification; separate supported completion from deterministic capacity refusal. Include
exact/over snapshot and delivery byte boundaries, including signed carrier overhead. At M5 record
actual published Plant/Bed count/bytes and native/portable route choice before acceptance; do not
infer whole-store feasibility from the 128-fact fixture.
No speed threshold justifies incomplete evidence, hashes changing or omission of current-source
checks. Baselines are measurements, not invented estimates or proof of incremental performance.
