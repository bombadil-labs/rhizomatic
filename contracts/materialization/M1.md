# M1 codec implementation and evidence

The accepted behavior is canonical [SPEC-16](../../spec/16-materialization.md), MR-04–MR-07.
Only lossless evidence codecs are implemented here. M2 gather/resolve commands, M3 control
lifecycle, M4 facade and M5 Loam integration remain prospective. No receiver authorization or
execution proof follows from decoding an envelope. Retaining an envelope retains full original
payloads; the retaining application owns those erasure surfaces.

## Callable ports and owners

| Owner | TypeScript | Rust |
|---|---|---|
| syntax | encodeReadingAppearance / decodeReadingAppearance | encode_reading_appearance / decode_reading_appearance |
| algebra | encodeHViewEnvelope / decodeHViewEnvelope | encode_hview_envelope / decode_hview_envelope |

All four return/accept canonical bytes and an explicit optional lowered limit configuration
(TS defaults when omitted; Rust passes ReadingAppearanceLimits/HViewEnvelopeLimits::default()).
Errors are EvidenceCodecError with invalid-evidence/resource-limit. Full native reading metadata,
original claims/signatures, authored slot indices, repeats and annotations survive. Rust owned
children cannot form native object cycles; TS explicitly rejects cycles. Reading reference keys
are full appearance commitments, while existing schemaHash/HView identity remains unchanged.
The explicit reserved-key correction is recorded in [E23](../../spec/02-operators.ERRATA.md).

The actual command API inventories classify these pure ports without moving owners. Parser
container guards are delta-owned native helpers; syntax counts explicit semantic family positions,
with no command/source capability. Core modules have no ambient I/O or clock.

## Independent expected bytes

[evidence-envelope.json](../../vectors/materialization/evidence-envelope.json) spells the wire
grammar using established C/hash/sign primitives, independently of all M1 codecs. Its generator
never imports the new envelope/reading codecs. It separately spells the old HView render so
validity omission and metadata-independent semantic pins are checked against their older ABI.
[independent-empty-oracles.json](../../vectors/materialization/independent-empty-oracles.json)
adds a separate Python grammar derivation with no witness imports. The initial raw UTF-8 ordering
oracle was withdrawn: existing C sorts complete encoded CBOR key bytes (SPEC-1 §4.1/D4).

All 15 stable M1 cases remain allocated in ACCEPTANCE/MILESTONES. Executed evidence is generated
separately; original M0 prospective capability cards are not runtime certificates. The inline
Schema budget probe does not claim that reflective policy syntax is legal: its semantic count is
pinned, then the existing native grammar still refuses it.

## Reproduce

From the repository root with Node/npm and stable cargo/rustc on PATH:

```
npm ci --ignore-scripts --prefix implementations/ts
npm run gen-evidence-vectors --prefix implementations/ts
node contracts/materialization/validate.mjs --self-test
node tools/check-command-contracts.mjs --self-test
node tools/check-package-graph.mjs
node tools/check-rust-command-boundaries.mjs
node tools/check-evidence-acceptance.mjs
node tools/check-evidence-towers.mjs --replay artifacts/materialization-m1
```

The acceptance gate serializes TS and Rust focused suites, verifies discovered stable case IDs,
then runs fresh-process JSON ports. Original/metadata/legacy/reserved-key fixtures each run
TS→Rust and Rust→TS, plus three seeded mixed codec assignments and exact replay. With two codec
stages and two capable witnesses there are exactly two distinct mixed assignments; the third is
explicitly marked repeatedFrom by the unchanged command planner. Retained plans carry build
identities, capability fingerprints, original artifacts and exact receiving results. --replay uses
retained plans without resampling and refuses unavailable/mismatched builds. Deliberate corruption
at the receiving boundary must fail. Elixir/Haskell remain honest Level 0 witnesses and advertise
no M1 codec stage.

M1_ARTIFACT_DIR chooses the evidence directory; M1_SEED chooses the recorded seed. CI runs M0
structure and M1 acceptance/replay after all four existing witness gates. Artifacts include
COVERAGE.json, TS-TESTS.json, rust.log, CAPABILITIES.json, EVIDENCE.json and per-fixture plans/stages.
Full TS/Rust gates, profile1 acceptance and vector/docs freshness remain required independently.
Independent Fable review is supervisor-owned after a clean frozen local commit; these gates alone
are not review acceptance.

Builder execution and host limitations: [M1-RESULTS.md](M1-RESULTS.md). Exact source-pinned
evidence is generated separately; independent review acceptance remains pending.

Accepted M1 baseline and bounded F1/A1/A2/A3 follow-up: [M1-FOLLOWUP.md](M1-FOLLOWUP.md).
The acceptance gate also emits VECTOR-ASSERTIONS.json and honors an external CARGO_TARGET_DIR
by using Cargo’s reported executable path. Performance evidence stays outside semantic goldens.
